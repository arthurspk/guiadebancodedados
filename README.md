## :dart: O guia para alavancar a sua carreira

> Banco de dados é a base de qualquer sistema que guarda informação: de um app de lista de tarefas a uma plataforma bancária. Este guia reúne trilha de estudo, documentação oficial, cursos gratuitos e pagos, livros, ferramentas, projetos práticos e um capítulo dedicado a usar IA na prática com bancos relacionais (PostgreSQL, MySQL, SQL Server, Oracle) e NoSQL (MongoDB, Redis) — tudo verificado e organizado para quem está começando a modelar sua primeira tabela ou quer se aprofundar em performance, replicação e bancos vetoriais.

## 💡 Nossa proposta

> A proposta deste guia é dar uma ideia sobre o atual panorama e guiá-lo se você estiver confuso sobre qual será o seu próximo aprendizado, sem influenciar você a seguir os 'hypes' e 'trends' do momento. Acreditamos que com um maior conhecimento das diferentes estruturas e soluções disponíveis poderá escolher a ferramenta que melhor se aplica às suas demandas. E lembre-se, 'hypes' e 'trends' nem sempre são as melhores opções.

## :beginner: Para quem está começando agora

> Não se assuste com a quantidade de conteúdo apresentado neste guia. Acredito que quem está começando pode usá-lo não como um objetivo, mas como um apoio para os estudos. <b>Neste momento, dê enfoque no que te dá produtividade e o restante marque como <i>Ver depois</i></b>. Ao passo que seu conhecimento se torna mais amplo, a tendência é este guia fazer mais sentido e ficar fácil de ser assimilado. Bons estudos e entre em contato sempre que quiser! :punch:

## 📖 Documentação oficial

> Bancos relacionais

- [PostgreSQL — Documentação oficial](https://www.postgresql.org/docs/current/) — A referência completa do PostgreSQL 18; tudo que você precisa está aqui.
- [PostgreSQL — Tutorial oficial](https://www.postgresql.org/docs/current/tutorial.html) — Introdução oficial: instalação, primeiras consultas, views, chaves estrangeiras e transações.
- [PostgreSQL — Using EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html) — Como ler o plano de execução de uma consulta — a habilidade que separa quem otimiza de quem chuta.
- [SQL Server — Documentação técnica (PT-BR)](https://learn.microsoft.com/pt-br/sql/sql-server/) — Documentação oficial do SQL Server em português, incluindo o SQL Server 2025.
- [Transact-SQL — Referência (PT-BR)](https://learn.microsoft.com/pt-br/sql/t-sql/language-reference) — Referência de todos os comandos T-SQL em português.
- [Tutorial: escrever instruções Transact-SQL (PT-BR)](https://learn.microsoft.com/pt-br/sql/t-sql/tutorial-writing-transact-sql-statements) — Tutorial oficial curto para criar banco, tabela e consultas no SQL Server.
- [Oracle Database — Documentação](https://docs.oracle.com/en/database/oracle/oracle-database/) — Portal de documentação do Oracle Database (versões 19c a 26ai).
- [Oracle — SQL Language Reference](https://docs.oracle.com/en/database/oracle/oracle-database/26/sqlrf/) — Referência completa da sintaxe SQL do Oracle.
- [Oracle — Database Concepts](https://docs.oracle.com/en/database/oracle/oracle-database/26/cncpt/) — O 'livro de conceitos' do Oracle: arquitetura, transações, armazenamento e segurança.
- [MariaDB — Documentação](https://mariadb.com/docs) — Documentação do MariaDB, fork compatível com MySQL (o site de docs do MySQL bloqueia verificadores automáticos, por isso não está listado).
- [SQLite — Documentação](https://www.sqlite.org/docs.html) — Documentação do SQLite, incluindo a página 'Appropriate Uses' para saber quando usá-lo.

> Bancos NoSQL

- [MongoDB — Manual (PT-BR)](https://www.mongodb.com/pt-br/docs/manual/) — Manual oficial do MongoDB traduzido para português.
- [MongoDB — Modelagem de dados (PT-BR)](https://www.mongodb.com/pt-br/docs/manual/data-modeling/) — Padrões de modelagem de documentos: embutir vs. referenciar, esquemas flexíveis e anti-padrões.
- [MongoDB — Operações de agregação (PT-BR)](https://www.mongodb.com/pt-br/docs/manual/aggregation/) — O pipeline de agregação, o 'GROUP BY' do mundo dos documentos.
- [Redis — Documentação](https://redis.io/docs/latest/) — Documentação oficial do Redis 8: tipos de dados, comandos, persistência e busca vetorial.
- [Redis — Tipos de dados](https://redis.io/docs/latest/develop/data-types/) — Strings, hashes, listas, sets, sorted sets, streams e mais, com exemplos.
- [Apache Cassandra — Documentação](https://cassandra.apache.org/doc/latest/) — Banco colunar distribuído usado em cargas massivas de escrita.
- [Neo4j — Documentação](https://neo4j.com/docs/) — Banco de grafos e a linguagem Cypher.
- [Amazon DynamoDB — Developer Guide](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html) — Guia oficial do banco chave-valor serverless da AWS.
- [Azure Cosmos DB — Documentação (PT-BR)](https://learn.microsoft.com/pt-br/azure/cosmos-db/) — Banco multimodelo da Microsoft (documentos, grafos, tabelas) em português.
- [Firestore — Documentação (PT-BR)](https://firebase.google.com/docs/firestore?hl=pt-br) — Banco de documentos do Firebase, muito usado em apps mobile.
- [Supabase — Documentação](https://supabase.com/docs) — PostgreSQL gerenciado com API, autenticação e vetores; alternativa open source ao Firebase.

> Modelagem e boas práticas

- [Modelo entidade-relacionamento (Wikipédia PT)](https://pt.wikipedia.org/wiki/Modelo_entidade_relacionamento) — Entidades, atributos, relacionamentos e cardinalidade — o vocabulário básico da modelagem.
- [Normalização de dados (Wikipédia PT)](https://pt.wikipedia.org/wiki/Normaliza%C3%A7%C3%A3o_de_dados) — As formas normais (1FN a 5FN) explicadas com exemplos.
- [ACID (Wikipédia PT)](https://pt.wikipedia.org/wiki/ACID) — Atomicidade, consistência, isolamento e durabilidade — o que uma transação garante.
- [Teorema CAP (Wikipédia PT)](https://pt.wikipedia.org/wiki/Teorema_CAP) — Por que bancos distribuídos precisam escolher entre consistência e disponibilidade.
- [AWS — O que é um banco de dados NoSQL? (PT-BR)](https://aws.amazon.com/pt/nosql/) — Explicação clara dos tipos de NoSQL (chave-valor, documento, grafo, coluna) e quando usar cada um.
- [Google Cloud — O que é um banco de dados relacional? (PT-BR)](https://cloud.google.com/learn/what-is-a-relational-database?hl=pt-br) — Introdução em português a bancos relacionais e SGBDs.
- [IBM — What is data modeling?](https://www.ibm.com/think/topics/data-modeling) — Modelos conceitual, lógico e físico e as técnicas mais usadas.
- [Guia de Estilo SQL (Simon Holywell) — PT-BR](https://www.sqlstyle.guide/pt-br/) — Convenções de nomes, indentação e formatação para SQL legível.
- [PostgreSQL Wiki — Don't Do This](https://wiki.postgresql.org/wiki/Don%27t_Do_This) — Lista oficial de coisas que você não deve fazer no PostgreSQL (e o que fazer em vez disso).
- [Modern SQL](https://modern-sql.com/) — Recursos do SQL pós-1992 (window functions, CTEs, JSON) e quais bancos suportam cada um.
- [Use The Index, Luke!](https://use-the-index-luke.com/) — Livro online gratuito sobre índices e performance de SQL para desenvolvedores.
- [PostgreSQL Wiki — Performance Optimization](https://wiki.postgresql.org/wiki/Performance_Optimization) — Ponto de partida oficial para tuning de PostgreSQL.

## 🤖 IA na prática

Bancos de dados e IA se cruzam de duas formas: usar assistentes de IA para trabalhar melhor com bancos, e usar bancos (vetoriais) para dar memória e contexto a aplicações de IA.

**Para aprender**
- Cole o resultado de um `EXPLAIN ANALYZE` e peça: *"explique este plano de execução e onde está o gargalo"*.
- Peça para gerar um MER (modelo entidade-relacionamento) a partir de uma descrição em texto do seu sistema, depois peça o `CREATE TABLE` correspondente e revise cada chave estrangeira e tipo de coluna.
- Peça exercícios de SQL com gabarito sobre o tópico que está estudando (joins, window functions, subqueries correlacionadas).
- Peça para comparar duas abordagens de modelagem (ex.: normalizado vs. desnormalizado) para um caso de uso específico e explicar o trade-off.

**Para trabalhar**
- Ferramentas de **text-to-SQL** (Vanna, WrenAI, Chat2DB) e assistentes com **MCP** conectam um LLM ao seu banco para consultar, analisar índices e sugerir otimizações em linguagem natural.
- Ao conectar um assistente de IA a um banco real, use sempre um **usuário somente leitura** (ou um banco de homologação) — nunca dê a um agente credenciais com permissão de `DELETE`/`DROP` sem revisão humana no meio do caminho.
- Use IA para gerar e revisar migrações, mas rode sempre em um ambiente de teste antes de aplicar em produção.
- **Bancos vetoriais** (pgvector, Qdrant, Weaviate, Redis, MongoDB Atlas Vector Search) armazenam embeddings para buscas por similaridade — a peça central de qualquer aplicação de RAG (Retrieval-Augmented Generation).

**Limites e boas práticas**
- Modelos ainda erram em SQL complexo: o benchmark [BIRD](https://bird-bench.github.io/), com bancos grandes e "sujos", mostra taxas de acerto bem menores que em bancos de exemplo simples. Sempre confira o resultado antes de confiar nele.
- IA pode **inventar nomes de colunas e tabelas** que não existem no seu esquema real; sempre valide contra o schema.
- Nunca cole dados sensíveis, dados de clientes ou credenciais de produção em uma ferramenta de IA sem verificar a política de privacidade e a LGPD.
- Um comando `DELETE`/`UPDATE` sem `WHERE` sugerido por IA pode apagar uma tabela inteira — revise sempre antes de executar.

> Text-to-SQL e assistentes

- [Vanna](https://vanna.ai/) — Framework open source de text-to-SQL com RAG: treine com seu esquema e pergunte em linguagem natural.
- [WrenAI](https://github.com/Canner/WrenAI) — Text-to-SQL governado por uma camada semântica; 'GenBI' open source.
- [DB-GPT](https://github.com/eosphoros-ai/DB-GPT) — Assistente de dados agêntico open source, com foco em privacidade (roda local).
